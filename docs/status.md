# Status

Last updated 2026-11-06. Nothing is released.

The hub runs at https://iris.klatt.ie behind Apache and Cloudflare, in place of the previous service.
A fresh Claude Code session with the plugin registered there, used the MCP tools and edited a file
through the hook. A `watch` stream stayed up through 125 s of idle time and delivered a notification
32 ms after a message was sent. All clients share one token, and there are no rate quotas yet.

## First milestone

From `docs/spec/requirements.md`:

| Step | State | Evidence |
|---|---|---|
| Two sessions register and see each other | Done on Linux | Claude Code and Copilot live. Windows: tests only |
| A message is received and acknowledged, and the sender sees it | Done on Linux | Live, across vendors |
| A claimed file is refused before the edit | Done on Linux | Live, across vendors. Deny proved in all seven clients' hooks and in a regression test for each |
| Dropped connection recovers every event in order | Done in tests | Reconnect during a burst, no loss and no duplicates |
| Hook latency measured on three systems | Done | CI runners, 100 pre-edit hooks with a real hub: see below |

| System | p50 | p95 | Target p95 |
|---|---|---|---|
| Linux amd64 | 8.8 ms | 9.6 ms | 50 ms |
| macOS arm64 | 11.1 ms | 29.2 ms | 50 ms |
| Windows amd64 | 25.5 ms | 32.3 ms | 150 ms |

On the development machine, with a slower disk, Linux measured p50 27.6 ms and p95 42.6 ms.

Linux, macOS and Windows all pass the test suite in CI, including the D4 guards run for real through
`cmd` and PowerShell. Six targets cross-build.

Live on Linux, Claude Code and Copilot collided on one file: Copilot was refused and left no file,
then messaged Claude, which read and acknowledged it and released the claim. An idle Claude session
with the plugin generated by `iris integrate` was woken by `iris watch`, then read and acknowledged a
message without any human input, 23.9 s after it was sent. Most of that is model time; the wake
signal alone measured 0.3 s in an earlier probe with a stand-in monitor.

## What exists

`iris serve`, `hook`, `mcp`, `watch`, `ui`, `integrate`, `setup`, `doctor`, `service`, `guard`, and
the operator console. `.goreleaser.yaml` validates and cannot publish.

## Not done yet

- A real client on Windows or macOS. Tests pass there; no agent has run there.
- `iris integrate` against a real client's own configuration: the real `claude plugin` install path,
  Codex's `/hooks` review, and whether Antigravity loads a user-level hook file. The Claude plugin
  passes `claude plugin validate`, and worked when loaded with `--plugin-dir`.
- `iris doctor --live`, and running a service for real under launchd, `systemd --user` and Task Scheduler.
- Package channels and signing (D15, stages 1 to 3).
- 100% coverage. The gate is in CI and red on purpose: Go is at 68.9% and the console at about 92%.
- A token per host, and rate limits on the public hub.
- Translations of the new console strings, and layout polish.
- Legal review of the clean-room record.

## Open SonarCloud findings

The quality gate is red on findings that were reviewed and kept on purpose:

- The session cookie has no `Secure` flag. It works on loopback only, over HTTP, and Safari would
  refuse a `Secure` cookie there.
- `web/src/api.ts` builds the WebSocket URL from `window.location`, with a fixed path.
- `PATH` lookups for `xdg-open` and for client binaries are how those commands are found.
